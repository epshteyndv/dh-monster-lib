## Context

Приложение уже использует Zustand для `encounter` и `partySize`; размер группы влияет на расчёт сложности и силы группы. Сейчас `partySize` меняется из шапки, а после перезагрузки возвращается к дефолту.

## Goals / Non-Goals

**Goals:**

- Ввести настройку `partySize` как часть пользовательских настроек, сохраняемую в `localStorage`.
- Обеспечить загрузку сохранённых настроек при старте приложения и немедленное применение к формулам сложности/силы.
- Перенести редактирование `partySize` из шапки в **Drawer слева**.
- Добавить точку входа в настройки из шапки (кнопка/иконка).

**Non-Goals:**

- Синхронизация настроек через URL.
- Серверное хранение или авторизация.
- Редизайн карточек монстров.

## Decisions

1. Использовать `persist` middleware Zustand с ключом, например `dh-monster-settings`, чтобы хранить минимум `partySize`.
2. Настройки вынести в отдельный store (`settingsStore`) или отделить persisted-слайс в текущем store; предпочтительно отдельный store для явной ответственности.
3. Для Drawer использовать Mantine `Drawer` с `position="left"`.
4. Валидировать `partySize` на чтении/записи (кламп в допустимый диапазон), чтобы повреждённый `localStorage` не ломал расчёт.

## Risks / Trade-offs

- **[Risk]** Устаревший/битый JSON в `localStorage` → **Mitigation:** безопасная десериализация + дефолты.
- **[Risk]** Дублирование состояния между encounter-store и settings-store → **Mitigation:** один источник истины для `partySize` (только settings-store).

## Migration Plan

Клиентская миграция без бэкенда: если ключа в `localStorage` нет, использовать дефолты; если есть — читать и применять.
