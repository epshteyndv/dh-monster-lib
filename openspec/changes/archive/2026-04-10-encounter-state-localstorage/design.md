## Context

Сейчас состояние энкаунтера активно синхронизируется с URL (`enc`), а `share`-flow тоже опирается на URL-канонизацию. После внедрения React Router это приводит к более сложному взаимодействию эффектов и query-параметров, чем нужно для повседневного редактирования.

## Goals / Non-Goals

**Goals:**

- Перенести «рабочее» сохранение текущего энкаунтера в `localStorage`.
- На старте приложения восстанавливать энкаунтер из `localStorage` (если нет более приоритетного входа по `share`).
- Сохранить отдельный `share`-entry flow: `share` применяется один раз, после чего URL очищается от `share` и приложение остаётся на основной странице.
- Убрать обязательную запись `enc` в URL на каждое изменение энкаунтера.

**Non-Goals:**

- Синхронизация состояния между разными браузерами/устройствами без явного share.
- Введение серверного хранилища состояния.
- Изменение структуры encounter в Zustand (instance-level identity сохраняется как есть).

## Decisions

1. Хранить в `localStorage` сериализованный payload того же типа `{ v, ids }`, чтобы переиспользовать текущую валидацию и codec-логику (`encode/decode` как fallback/совместимость helper-кода).
2. Приоритет источников при загрузке: `share` (если валиден) > `localStorage` > пустой энкаунтер.
3. После применения `share` удалять `share` из URL через replace-навигацию; `enc` в URL не использовать как «рабочий» state канал.
4. При каждом изменении encounter сохранять ids в `localStorage`; при пустом encounter удалять ключ или сохранять пустой payload (выбрать один вариант и закрепить в коде).

## Risks / Trade-offs

- **[Risk]** Потеря возможности «пассивно» делиться текущим URL без кнопки share → **Mitigation:** явный share-контрол остаётся и становится единственным рекомендованным способом обмена.
- **[Risk]** Локальное состояние может устаревать относительно каталога → **Mitigation:** при восстановлении, как и сейчас, пропускать неизвестные id.
- **[Risk]** Private mode / quota errors в `localStorage` → **Mitigation:** оборачивать запись/чтение в `try/catch`, не падать UI.

## Migration Plan

- Внедрить localStorage-persistence слой и переключить загрузку/сохранение на него.
- Оставить `share`-flow для импортирования состояния по ссылке.
- Проверить, что навигация/history больше не засоряется автозаписью `enc`.

## Open Questions

- Нужно ли мигрировать legacy `enc` на первом заходе (если `share` отсутствует) или полностью игнорировать `enc` в новом поведении. По умолчанию: игнорировать для текущего change, если не будет отдельного требования на миграцию.
