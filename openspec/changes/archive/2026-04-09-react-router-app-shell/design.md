## Context

Проект: Vite + React, статический деплой на GitHub Pages, `base` задаётся через `VITE_BASE_PATH` / конфиг Vite. Сейчас `main.tsx` монтирует `App` напрямую; синхронизация энкаунтера с URL реализована через `history.replaceState` и чтение `window.location.search`.

## Goals / Non-Goals

**Goals:**

- Подключить **React Router v6** (`react-router-dom`) как единственный задокументированный клиентский роутинг.
- Установить **`basename`** из `import.meta.env.BASE_URL` (с правилами нормализации слеша, принятыми в проекте и в документации React Router).
- Сохранить поведение: загрузка каталога, энкаунтер, `enc` / `share`, отсутствие лишних записей в history при обычном редактировании (эквивалент **`replace`**).

**Non-Goals:**

- Серверный SSR или отдельный backend для маршрутов.
- Миграция на file-based роутинг-фреймворки.
- Обязательное введение нескольких пользовательских «страниц» с уникальным контентом в первом PR (достаточно одной корневой маршрутизации + задел на расширение).

## Decisions

1. **API роутера:** `createBrowserRouter` + `RouterProvider` (data router) или `BrowserRouter` — выбрать минимально достаточный вариант; предпочтительно **один** чёткий паттерн на весь проект.
2. **Маршруты (начальный набор):** как минимум индексный маршрут `/`, рендерящий текущий функционал энкаунтера (хостится в отдельном компоненте страницы при рефакторинге).
3. **Query sync:** заменить прямые `URLSearchParams(window.location.search)` и `history.replaceState` там, где это уместно, на **`useSearchParams` + `setSearchParams(..., { replace: true })`** (или `useNavigate`) для канонизации `enc`/`share`, чтобы логика жила в контексте роутера.
4. **404 под GitHub Pages:** при SPA на Pages по-прежнему нужен fallback на `index.html` (вне scope кода приложения, но упомянуть в задачах документации репозитория при необходимости).

## Risks / Trade-offs

- **[Risk]** Неверный `basename` на вложенном Pages URL → **Mitigation:** тест под `VITE_BASE_PATH`, сравнение с текущим `vite.config` `base`.
- **[Risk]** Двойная синхронизацияURL (роутер + старый код) → **Mitigation:** единый путь обновления search после миграции эффекта.

## Migration Plan

- Добавить зависимость, обернуть приложение, затем перенести sync в router-aware API; удалить прямой `replaceState` из хука синхронизации, когда эквивалент подтверждён.
- Сборка и ручной прогон: открытие с `?enc=`, с `?share=`, редирект share→enc, редактирование энкаунтера.

## Open Questions

- Нужен ли отдельный маршрут для «чистой» лендинг-страницы в будущем — вне этого change.
