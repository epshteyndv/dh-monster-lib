## Why

Логика вокруг URL (энкаунтер, `enc`, `share`, синхронизация с `history`) и точка входа приложения всё больше опираются на ручной доступ к `window.location` и порядок эффектов в одном корневом компоненте. Это усложняет сопровождение и добавление маршрутов. **React Router** даёт явный каркас навигации и стандартные API для query/search, что упростит текущую запутанность и подготовит приложение к развитию.

## What Changes

- Добавить зависимость **`react-router-dom`** и обернуть UI в маршрутизатор с **`basename`**, согласованным с базой Vite/GitHub Pages.
- Вынести маршрутную конфигурацию (как минимум один маршрут для основного экрана энкаунтера) в отдельный слой (например `createBrowserRouter` + `RouterProvider` или эквивалент в актуальной major-версии пакета).
- Постепенно перевести работу с query-параметрами энкаунтера на API роутера (**`useSearchParams`**, навигация с **`replace`**) там, где это снижает связность с «сырым» `window`/`history`, **сохранив** семантику **Encounter state in URL**, **URL history behavior** и **Encounter share link entry and redirect** (если они уже внедрены в коде).
- Разделить «оболочку» и страницу энкаунтера по файлам/компонентам по мере необходимости, без изменения пользовательских сценариев.

## Impact

- `package.json` / lockfile — новая зависимость.
- `src/main.tsx` — провайдер маршрутизации.
- Новый модуль маршрутов и, при необходимости, `src/pages/EncounterPage.tsx` (или переименование текущего `App`).
- `src/useEncounterUrlSync.ts` (и вызовы из страницы энкаунтера) — миграция на `useSearchParams` / `useNavigate(..., { replace: true })` по задачам change.
