## Why

Один файл `data/monsters.yaml` не масштабируется: крупные наборы (например книга тиров) уже лежат отдельным YAML в `data/monsters/`. Сборка должна **собирать каталог из всех** `*.yaml` в этой папке, а не дублировать источник в корневом `data/monsters.yaml`.

## What Changes

- Скрипт сборки каталога (`build-catalog` / `monsters.json`) **читает только** YAML-файлы из **`data/monsters/`** (все файлы с расширением `.yaml` в этой директории), **объединяет** их содержимое в один список монстров с глобально уникальными `id`.
- Корневой **`data/monsters.yaml` перестаёт быть источником** для сборки; записи из него **переносятся** в один или несколько файлов под `data/monsters/` (или удаляются, если дублируют уже существующие данные).
- **BREAKING** для контрибьюторов: править нужно файлы в `data/monsters/`, а не единственный корневой YAML (если он использовался).
